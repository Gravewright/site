    Testes

    Django, node:test, Playwright e validação nativa com dados descartáveis.

    Documentação · English

    Execute na raiz após uv sync --locked. O projeto usa Django/unittest para Python, o executor nativo do Node para JavaScript e scripts Playwright independentes para navegador. Não há npm test na raiz nem executor pytest configurado.

    Limitações conhecidas no Windows

    • O Windows limita caminhos a 260 caracteres. Os cenários do Map Builder instalam um módulo de fixture dentro da pasta de saída; um --output longo, como um aninhado na pasta temporária do usuário, faz essa instalação falhar com "Invalid module archive". Use a saída padrão em data/ ou outro caminho curto.

    • tests/e2e/escape_windows.py não inicia servidor próprio. Ele precisa de ownership_server.py em 127.0.0.1:30002 e de data/permissions-review-seed.json dessa fixture.

    Ambiente local controlado

    Os testes carregam .env quando uma variável do processo não a substitui. Para testes HTTP locais, use um shell com estes valores em vez de herdar origem HTTPS de produção ou Redis externo:

    bash
    export DJANGO_DEBUG=true
export DJANGO_ALLOWED_HOSTS='127.0.0.1,localhost,[::1],testserver'
export GRAVEWRIGHT_PUBLIC_ORIGIN=''
export DJANGO_SECURE_COOKIES=false
export GRAVEWRIGHT_REDIS_URL=''
export TRUSTED_PROXIES=''
export GRAVEWRIGHT_MARKETPLACE_URL=''
export GRAVEWRIGHT_MARKETPLACE_KEYS_FILE=''
export GRAVEWRIGHT_RELEASES_REPOSITORY=''

    Isso altera apenas o shell, não o .env. Fixtures de navegador normalmente substituem banco e arquivos por diretórios temporários. Cada cenário pode sobrescrever configurações específicas.

    Python

    bash
    uv run --locked python manage.py check
uv run --locked python manage.py makemigrations --check --dry-run
uv run --locked python manage.py test config gravewright --noinput

    O executor usa explicitamente data/test-gravewright.sqlite3, em arquivo, para testar locks do SQLite. --noinput autoriza substituir esse banco de testes caso já exista. Não aponte para dados importantes nem execute suítes simultâneas no mesmo caminho. Alterar GRAVEWRIGHT_DATABASE não altera o nome explícito desse banco de testes. Testes que escrevem arquivos geralmente criam armazenamento temporário; use GRAVEWRIGHT_MEDIA_ROOT descartável como proteção adicional ao executar a suíte inteira.

    Exemplos focados:

    bash

uv run --locked python manage.py test gravewright.table.tests.test_frontend_api gravewright.modules --noinput
uv run --locked python manage.py test gravewright.dice --noinput

uv run --locked python tests/e2e/automatic_updates.py --runner

    Esses cenários usam dados isolados e verificam dependências, rotas Django, recuperação de falhas de migração, preservação nas atualizações e rollback .old.

    JavaScript

    Use Node.js atual com módulos ES nativos e node:test; estes comandos foram verificados com Node 24. Não é necessário instalar pacotes na raiz para esses testes.

    bash
    node --test tests/modules/*.test.mjs tests/effects/*.test.mjs

    Para incluir todos os testes JavaScript junto ao código, este lançador Python evita globs recursivos específicos do shell:

    bash
    uv run --locked python - <<'PY'
from pathlib import Path
import subprocess
files = sorted(str(p) for base in ('gravewright', 'tests')
               for p in Path(base).rglob('*')
               if p.name.endswith(('.test.js', '.test.mjs')))
subprocess.run(['node', '--test', *files], check=True)
PY

    A cobertura inclui ciclos de vida e contratos de módulos, parsing de shaders, entradas do tabuleiro, agendamento de tiles, visibilidade, paredes, seleção, rotas de tokens e mapeamento PDF. Testes de geometria/modelos não substituem a conferência da renderização real na GPU.

    Os testes de módulos cobrem uploads multipart de imagens de cartas na inicialização, duração de ativação, permissões nativas e operações canceladas. A suíte Django gravewright.modules.test_card_assets também verifica validação de imagens, reutilização de recursos, isolamento de mesas e limpeza após falha.

    Cenários no navegador

    uv run --locked python tests/e2e/door_rotation_anchor.py verifica a escolha do pivô da porta, rotação, desfazer, imagem ao abrir/fechar, editor compartilhado de paredes e configurações salvas em inglês, português e espanhol, em larguras de desktop e celular. Usa uma campanha isolada e aceita --output e --browser-executable.

    O cenário de gerenciamento de campanha usa dados descartáveis para exercitar fichas PDF nativas, editores de diários e missões, acesso de comestres, requisições negadas e revogação do acesso de mestre. Confere que o gerenciamento não abre WebSocket do jogo nem presença na mesa, comparando snapshots anteriores e posteriores da transmissão, da navegação privada de cenas e da presença. Também confere inglês, português e espanhol em larguras de celular e depois abre a mesa real para verificar documentos compartilhados, filtragem para jogadores e reprodução de áudio em dois clientes. Essa descrição informa a cobertura do cenário, não o resultado de uma execução.

    bash
    uv run --locked python tests/e2e/campaign_management.py --output data/cm-check --browser-executable "<existingChromium>"

    Substitua <existingChromium> por um executável Chromium existente. Escolha uma pasta de saída nova ou vazia a cada execução; fixtures, logs, comparações de estado e capturas ficam nessa pasta dentro da instalação.

    O cenário de preparação de campanha usa a mesma fixture descartável para exercitar o painel, o seletor de referências sem conexão com a mesa, o planejador de sessões, a cronologia e o calendário, as colunas de missões com pré-requisitos, as conexões, a prévia do jogador e a restauração de um diário pela lixeira, e confere layouts em largura de celular. Use as mesmas opções --output e --browser-executable do cenário acima.

    tests/e2e/campaign_preparation_regressions.py verifica preservação de rascunhos, edição durante o salvamento, erros e novas tentativas no seletor assíncrono de referências, comparação desatualizada durante edição por outro mestre, permissões de versões privadas e rejeição atômica de restauração histórica com arquivo físico ausente. Também verifica a mensagem nativa exata em inglês e suas traduções em português/espanhol em 320px. Use outra pasta de saída nova: uv run --locked python tests/e2e/campaign_preparation_regressions.py --output data/prep-regressions --browser-executable "<existingChromium>".

    gravewright.administration.test_preparation_archives cobre exportação e retorno da preparação e do histórico, arquivos retidos, painel de cada mestre em snapshots, compatibilidade com arquivos antigos, remapeamento de referências, cronologia e rejeição de metadados inválidos, donos conflitantes de anexos e ciclos de missões.

    O cenário dos relógios de progresso usa campanhas isoladas para verificar os mesmos relógios no gerenciamento e na mesa real, atualizações em tempo real, permissões de jogadores e espectadores, filtragem de relógios privados e por cena, versões concorrentes, persistência e exibição fixada. Também confere inglês, português e espanhol em 320px e preserva os limites de transmissão, navegação e presença do gerenciamento. Execute com uv run --locked python tests/e2e/clocks.py --output data/clocks-check --browser-executable "<existingChromium>", usando uma pasta de saída nova. A descrição informa a cobertura, não o resultado de uma execução específica.

    tests/e2e/map_builder_clocks.py confere nós nativos de relógio, conexões tipadas de Quantidade, continuação da execução, salvar/recarregar e ensaio sem alterações persistidas, comparando snapshots de relógios, recibos e mídia. Exercita vínculos do mestre acionados por jogadores, filtragem de relógios privados, HUD fixado em tempo real e edição de nós ao vivo para avançar, reduzir, definir e reiniciar, além de inglês, português e espanhol em desktop e 320px.     tests/e2e/clues.py cobre descobertas imediatas e progressivas no gerenciamento, na mesa e no editor nativo do MapBuilder. Confere a filtragem de registros desconhecidos e notas do mestre em JSON, eventos e DOM do jogador; revelar/ocultar, permissões, revisões, repetição de recibos, persistência, escopo de cena, exibição fixada e ensaio sem alterações persistidas. Nós de pistas exercitam entradas numéricas tipadas, continuação da execução e ações ao vivo de avançar, recuar, definir, reiniciar, revelar e ocultar. Inglês, português e espanhol são conferidos com conteúdo autoral longo em 320px e desktop. Execute em uma pasta local nova: uv run --locked python tests/e2e/clues.py --output data/clues-check --browser-executable "<existingChromium>".

    tests/e2e/progress_hud.py verifica cards e segmentos vazios transparentes de relógios/pistas, indicadores fixados mínimos, controles pelos botões esquerdo/direito, permissões e posições locais independentes com vários clientes reais. Dois cliques no nome abrem o editor nativo para mestres e uma descrição somente de leitura para jogadores/espectadores. Descrições longas ou vazias e revogação durante leituras pendentes exercitam o ciclo de vida da modal e a privacidade. Compara requisições, mensagens do socket e estado persistido para conferir que mover um indicador não publica uma alteração da campanha; depois verifica posições após recarregar e layouts em inglês/português/espanhol em 320px. Use uma saída nova: uv run --locked python tests/e2e/progress_hud.py --output data/progress-hud-check --browser-executable "<existingChromium>". A suíte Django gravewright.realtime.tests.test_token_refresh_cost verifica o custo das notificações, estabilidade da projeção de atores, áudio independente e revogação de acesso durante a entrega.

Encerre cada servidor pertencente ao teste depois da execução.

Também aceita --browser-executable.
