    Como criar um módulo de ferramentas de combate

    Crie laboratório de encontro com participantes, iniciativa, ordem, estados, turnos, rodadas e limpeza.

    O projeto que você vai criar

    Crie Combat workshop e opere o encontro nativo de uma cena descartável. Adicione dois tokens, defina/role iniciativa, inicie, selecione/reordene, avance turnos/rodadas e finalize removendo participantes. O sistema de RPG escolhido continua responsável por suas regras e provedor.

    Host alvo: Gravewright 0.3.0. As ações rodam somente quando você clica Run action; leituras e escritas usam a conta conectada. O painel de demonstração está em inglês. Cada receita abaixo informa os dados de entrada e o resultado concreto.

    1. Crie os arquivos

    Crie uma pasta combat-workshop. Salve os arquivos mostrados abaixo em UTF-8, ou baixe o projeto completo. manifest.json fica na raiz. Não há dependências npm nem build de JavaScript.

    text
    combat-workshop/
  manifest.json
  main.mjs
  recipes.mjs
  styles.css
  LICENSE.txt

    Mantenha cena e dois tokens do Token workshop. Execute Inspect para IDs reais de cena/combatente. Use tokenId para token colocado ou actorId para participante só de ator. O módulo não fornece sistema, catálogo nem complemento Server Rules. A fórmula explícita de teste é ajuste do encontro na campanha descartável.

    2. Empacote, instale e ative

    Partindo da pasta do projeto, execute no PowerShell:

    powershell
    python -m json.tool manifest.json
python -m zipfile -c ../combat-workshop-1.0.0.zip manifest.json main.mjs recipes.mjs styles.css LICENSE.txt
python -m zipfile -l ../combat-workshop-1.0.0.zip

    No Linux/macOS, substitua python por python3 no mesmo comando. A listagem precisa mostrar manifest.json na raiz. Como proprietário, abra Inside → Módulos → Instalar módulo → Instalar de ZIP, selecione o ZIP e clique Instalar. Como GM, abra a campanha, use o botão Gravewright da mesa → Extensions e clique Activate na versão 1.0.0 de Combat workshop. Feche o menu e clique no botão Combat workshop. Se precisar de detalhes de cada tela, veja seu primeiro módulo.

    O projeto fica inativo até a seleção na mesa. Teste uma extensão de demonstração por vez, pois seus botões usam a mesma posição. Para novos bytes, mude version para 1.0.1, gere outro ZIP, instale e ative essa versão; não edite o pacote instalado.

    3. Execute cada receita

    Consultar encontro desta cena

    Cole ID da cena descartável. Ainda pode não existir encontro. Após adicionar participantes, copie IDs da lista projetada.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    return await api.combat.state({sceneId:v.mapId},read);
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Versão, active/round/turn, configuração e combatentes autorizados.

    Como conferir: Compare com Combat nativo. Jogador não deve receber entradas ocultas ou recursos não autorizados.

    Adicionar token ou ator ao combate

    Use tokenId com os dois IDs do tutorial de tokens, uma execução por token. Ou actorId para ator sem token na cena. Cada Run action é uma operação.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    if(!['tokenId','actorId'].includes(v.identityType)) throw new Error('Use tokenId or actorId');
    const identity={[v.identityType]:v.id};
    const before=await api.combat.state({sceneId:v.mapId},read);
    return await api.combat.add({sceneId:v.mapId,version:before.version,...identity},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Combatente adicionado sem duplicar identidade existente; versão avança.

    Como conferir: Adicione dois combatentes distintos e confira no rastreador. Token de outra cena deve ser recusado.

    Definir fórmula explícita de iniciativa

    Só no encontro descartável, defina expressão genérica1d20. O sistema selecionado é dono da fórmula/provedor padrão; este ajuste nativo explícito não implementa regras de RPG. Limpe o campo para modo manual.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const before=await api.combat.state({sceneId:v.mapId},read);
    return await api.combat.configure({sceneId:v.mapId,version:before.version,formula:v.formula.trim()},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Config.formula reflete a expressão; config.input informa a entrada conforme sistema.

    Como conferir: Abra ajustes de Combat e confira. Fórmula inválida é rejeitada sem gravação parcial.

    Definir iniciativa de um combatente

    Use identidade participante. A receita respeita config atual: texto continua texto e entrada numérica/rolada vira número finito. Não fixe atributo de um sistema.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    if(!['tokenId','actorId'].includes(v.identityType)) throw new Error('Use tokenId or actorId');
    const identity={[v.identityType]:v.id};
    const before=await api.combat.state({sceneId:v.mapId},read);
    const value=before.config?.input==='text'?v.value:Number(v.value);
    if(typeof value==='number'&&!Number.isFinite(value)) throw new Error('Enter a finite initiative number');
    return await api.combat.setInitiative({sceneId:v.mapId,version:before.version,...identity,value},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Iniciativa selecionada alterada; números seguem a ordenação nativa.

    Como conferir: Defina12 e8 para dois participantes e confira. Sistemas em modo texto podem manter ordem manual.

    Rolar iniciativa para um escopo

    Configure fórmula válida antes. Missing rola só valores ausentes; all refaz todos; npcs usa regras nativas de posse; one usa a identidade participante informada.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    if(!['all','missing','npcs','one'].includes(v.scope)) throw new Error('Choose an initiative scope');
    const before=await api.combat.state({sceneId:v.mapId},read);
    if(!before.config?.formula) throw new Error('Configure an initiative formula first');
    const identity={};
    if(v.scope==='one'){
      if(!v.id||!['tokenId','actorId'].includes(v.identityType)) throw new Error('Supply the selected combatant identity');
      identity[v.identityType]=v.id;
    }
    return await api.combat.rollInitiative({sceneId:v.mapId,version:before.version,scope:v.scope,...identity},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Só o escopo escolhido recebe rolagens de servidor; o rastreador ordena resultados.

    Como conferir: Defina um valor manual, execute missing e confirme preservação. Não presuma resultado fixo de rolagem.

    Mover participante para cima ou baixo

    Use combatente e execute up, depois down. Reordenar preserva identidade do combatente ativo, sem passar o turno silenciosamente.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});

    throw problem;
  }
}

    Resultado esperado: Participante muda de posição e identidade ativa é preservada.

    Como conferir: Inicie combate, anote ID atual e reordene outra entrada. O participante atual deve continuar o mesmo.

    Definir oculto e derrotado explicitamente

    As opções definem booleanos exatos, sem inverter estado desconhecido. Entradas derrotadas são puladas no avanço. Desmarque ambas para restaurar o participante.

    javascript

    Resultado esperado: Entrada com as opções escolhidas. Entrada de combate oculta ausente para jogadores.

    Como conferir: Compare rastreador GM/jogador e retire defeated antes de testar o ciclo completo.

    Iniciar ou parar encontro descartável

    Adicione ao menos dois participantes. Start cria identidade de encontro e começa round1/turn0. Stop limpa cursor/histórico ativos, mantendo participantes. Use só o encontro de teste.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const before=await api.combat.state({sceneId:v.mapId},read);
    const payload={sceneId:v.mapId,version:before.version};
    if(v.action==='start') return await api.combat.start(payload,write());
    if(v.action==='stop') return await api.combat.stop(payload,write());
    throw new Error('Choose start or stop');
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Start: active true, round1. Stop: active false, round0.

    Como conferir: Confira encounterId e rastreador após cada ação intencional.

    Selecionar participante atual específico

    Inicie primeiro e use identidade participante. Isso seleciona posição sem fingir que turnos pulados executaram efeitos normais.

    Avançar ou retornar um turno

    Inicie antes. Next avança relógios nativos e pula derrotados. Jogador autorizado pode encerrar seu turno atual; previous é de GM e exige histórico.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const before=await api.combat.state({sceneId:v.mapId},read);
    if(!before.active) throw new Error('Start combat first');
    const payload={sceneId:v.mapId,version:before.version};
    if(v.direction==='next') return await api.combat.nextTurn(payload,write());
    if(v.direction==='previous'){
      if(context.role!=='gm') throw new Error('GM required for previous turn');
      return await api.combat.previousTurn(payload,write());
    }
    throw new Error('Choose next or previous');
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.combat.state({sceneId:v.mapId},read);
    throw problem;
  }
}

    Resultado esperado: Identidade atual muda conforme ordem nativa; previous retorna o cursor salvo quando existe.

    Como conferir: Tente next como controlador atual e outro jogador. Só o primeiro pode. Retornar não ressuscita condições expiradas nem desfaz efeitos periódicos.

    Avançar ou retornar uma rodada

    Use next para avançar rodada e previous para conferir o cursor nativo. Avanço pode consumir duração de condições/efeitos. Previous navega, sem desfazer efeitos persistidos.

    Remover só participante de combate do tutorial

    Pare o encontro de teste e remova participantes um por vez. Isso remove participação no rastreador, sem apagar token/ator.

    Como conferir: Confirme que token permanece e, se desejar, remova-o pela receita separada de tokens.

    4. Entenda e adapte os arquivos completos

    main.mjs desenha apenas o lançador e o formulário. recipes.mjs contém as ações: para adaptar o comportamento, altere a função run da receita desejada, mantendo sua assinatura. O formulário passa tipos reais (number, boolean e File), bloqueia requisições simultâneas e desenha resultados com textContent. Não há avaliação de código fornecido pelo usuário. api, host, assets e storage pertencem à montagem; signal cancela trabalho ao desativar. O modal não fecha durante uma operação pendente e é liberado ao abortar a montagem. A função de negócio continua responsável por revisões, permissões e sequência transacional.

    5. Permissões, falhas e teste final

    Cada gravação exige Run action explícito. Leituras usam projeções autorizadas; escritas mantêm permissões nativas e UUID novo por operação. Update de cena/objeto, movimento/configuração de token e combate usam seus campos reais de revisão. Alguns comandos nativos de seleção não aceitam revisão esperada nesta versão; os exemplos não inventam esse parâmetro. Em conflito, a receita relê o estado e para. Revise e execute conscientemente nova operação. Chamadas diferentes são transações distintas: uma já concluída não é revertida se uma leitura posterior falhar. Desativar aborta trabalho da montagem, sem desfazer commit.

    Teste dois participantes, jogador encerrando o próprio turno, outro jogador negado, todos derrotados, histórico anterior ausente, revisão antiga e abort. Avançar relógios pode expirar condições ou aplicar efeitos do sistema. Previous turn/round muda cursor, sem desfazer efeitos persistidos ou restaurar condições. A identidade ativa permanece ao reordenar.
