    How to create a token tools module

    Place, move, duplicate, configure and remove tokens; control native vision/visibility and timed conditions.

    The project you will build

    Build Token workshop as one browser module. Place two disposable tokens in the scene from the previous tutorial, then test movement, snapshot duplication, rotation/elevation, vision, hidden state and an original condition. Keep the tokens for the combat tutorial before removal.

    Target host: Gravewright 0.3.0. Actions run only when you click Run action, using the signed-in account. The demonstration panel is English. Each recipe specifies inputs and an observable result.

    1. Create the files

    Create a folder named tokens-workshop. Save the complete files below as UTF-8, or download the project. manifest.json belongs at the root. No npm dependencies or JavaScript build is required.

    text
    tokens-workshop/
  manifest.json
  main.mjs
  recipes.mjs
  styles.css
  LICENSE.txt

    Complete Scene workshop and keep its scene ID. Create a disposable actor with the selected system through the native Actors directory, or follow the actor tutorial. Copy actual IDs from Inspect. The module calls public api.tokens methods. Its gridX/gridY are cell-space placement coordinates; native wall geometry uses scene pixels.

    2. Package, install and activate

    From the project folder, run in PowerShell:

    powershell
    python -m json.tool manifest.json
python -m zipfile -c ../tokens-workshop-1.0.0.zip manifest.json main.mjs recipes.mjs styles.css LICENSE.txt
python -m zipfile -l ../tokens-workshop-1.0.0.zip

    On Linux/macOS, replace python with python3 in the same commands. The archive listing must show manifest.json at its root. As installation owner, open Inside → Modules → Install module → Install from ZIP, select the ZIP and click Install. As GM, open the campaign, select its Gravewright button → Extensions and Activate version 1.0.0 of Token workshop. Close that menu and click Token workshop. See your first module for screen-by-screen instructions.

    The package stays inactive until selected for the table. Test one demonstration extension at a time because their launchers share a position. For changed bytes, increment version to 1.0.1, build another ZIP, install and activate that version; do not edit installed files.

    3. Run each recipe

    Inspect available actors and scene tokens

    Paste the test Scene ID from the maps tutorial. Copy a readable actor ID for Place, then a token ID for later actions.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    return {actors:await api.actors.list({},read),tokens:await api.tokens.list({mapId:v.mapId},read)};
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: Authorized actor metadata and token IDs, versions, positions, vision and visible conditions.

    How to verify: Compare GM and player: hidden tokens and GM-only conditions are filtered before delivery.

    Place an actor token in the test scene

    Create an original disposable actor using the native/system sheet first. Coordinates use cell-space gridX/gridY for token placement, not scene pixels. The host validates bounds and token size.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    await api.actors.get(v.actorId,{},read);
    const created=await api.tokens.place({mapId:v.mapId,actorId:v.actorId,gridX:v.x,gridY:v.y},write());
    return {createdIds:created.createdIds,tokens:created.tokens};
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: A created token ID and current token projection. The host decides linked/snapshot mode.

    How to verify: Find the token at grid2,2. A first token may be linked; another placement of the same actor may turn existing links into independent snapshots through the native service.

    Move a controlled unlocked token

    Enter the token ID and a nearby destination. path:[] requests the direct segment; intermediate waypoints must use the same grid coordinates. Player movement still checks walls and ownership.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const token=await api.tokens.get(v.id,{mapId:v.mapId},read);
    if(!token.canControl||token.locked) throw new Error('Choose a controlled unlocked token');
    return await api.tokens.move({mapId:v.mapId,id:token.id,expectedVersion:token.version,gridX:v.x,gridY:v.y,path:[]},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: The same token at its accepted grid position with an incremented version.

    How to verify: Test as its controlling player: an unlocked open path succeeds, a wall-blocked path fails and leaves the position unchanged. An old expectedVersion conflicts.

    Duplicate one tutorial token

    Use the token placed above. The native service creates an independent snapshot and chooses its bounded offset.

    Expected result: A different token ID, usually offset by one cell, with linkMode snapshot.

    How to verify: Inspect both IDs and open their sheets. Copy the duplicate ID for cleanup or combat.

    Configure rotation, elevation and disposition

    Configure a single disposable token. Keep locked false for the movement recipe. Elevation can affect region eligibility. A player may rotate a controlled token only with the rotation-only values variant; this multi-field recipe is GM-only.

    Expected result: Requested native rotation, elevation, disposition and locked state, retaining actor/sheet data.

    How to verify: Inspect the native token configuration and confirm locked prevents a later move until explicitly cleared.

    Enable and configure token vision

    Use the placed token; range is a nonnegative cell distance. To observe line-of-sight, configure dynamic lighting in the native scene and use the token controlling player.

    Run with Hidden selected, inspect the player account, then clear it and run again. This changes token visibility, not the actor permission map.

    Add an original timed token condition

    Use an original label. This is a generic marker, not a bundled rule. Copy condition_id from the result for Remove condition. Duration advances through real forward combat events when the token participates.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    await api.tokens.get(v.id,{mapId:v.mapId},read);
    if(!['everyone','gm'].includes(v.visibility)) throw new Error('Use everyone or gm');
    if(!Number.isInteger(v.rounds)||v.rounds<1) throw new Error('Use a positive integer duration');
    if(v.visibility==='gm'&&context.role!=='gm') throw new Error('GM required for hidden conditions');
    await api.tokens.addCondition({mapId:v.mapId,tokenIds:[v.id],label:v.label,description:'Original tutorial marker with no RPG rules.',kind:'positive',visibility:v.visibility,duration:{type:'rounds',value:v.rounds,expires:'end'}},write());
    return await api.tokens.get(v.id,{mapId:v.mapId},read);
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: A new condition with unique condition_id and an explicit rounds/end duration.

    How to verify: As player, add only to a controlled token with visibility everyone. A private GM condition must be absent from player state.

    Remove the chosen token condition

    Paste the exact condition_id, not its display label. Remove only the marker created in this tutorial.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const token=await api.tokens.get(v.id,{mapId:v.mapId},read);
    if(!token.conditions.some(item=>item.condition_id===v.conditionId)) throw new Error('Choose a visible condition from this token');
    await api.tokens.removeCondition({mapId:v.mapId,tokenIds:[v.id],conditionId:v.conditionId},write());
    return await api.tokens.get(v.id,{mapId:v.mapId},read);
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: The selected condition disappears while other conditions remain.

    How to verify: Inspect before/after. A player cannot discover/remove a GM-only condition by guessing its ID.

    Remove the disposable token

    Use only the tutorial token/duplicate. Run after combat cleanup. Removing a token does not delete its actor.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    if(!v.confirm) throw new Error('Confirm the disposable token');
    await api.tokens.get(v.id,{mapId:v.mapId},read);
    await api.tokens.remove({mapId:v.mapId,tokenIds:[v.id]},write());
    return await api.tokens.list({mapId:v.mapId},read);
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.tokens.state({mapId:v.mapId},read);
    throw problem;
  }
}

    Expected result: The selected token is absent; its actor remains in Actors.

    How to verify: Check the scene and actor directory, and confirm other token IDs remain.

    4. Understand and adapt the complete files

    main.mjs renders the launcher and form. recipes.mjs owns behavior: change the chosen recipe’s run function while keeping its signature. The form passes real number, boolean and File values, blocks overlapping requests and renders using textContent. It does not evaluate user-provided code. api, host, assets and storage belong to the mount; signal cancels work on deactivation. The modal stays open during pending work and is released when the mount aborts. Each business function remains responsible for revisions, permissions and transaction sequencing.

    import {recipes} from './recipes.mjs';
export default {
  start({styles}) { styles.use('styles.css'); },
  register({register}) {
    register("table.interface", ({root,api,host,assets,storage,context,events,viewport,signal,onDispose}) => {
      const doc=root.ownerDocument;
      const button=doc.createElement('button');
      button.type='button';button.className='tutorial-launcher';
      button.textContent="Token workshop";
      root.append(button);
      for(const type of ['pointerdown','mousedown'])button.addEventListener(type,event=>event.stopPropagation(),{signal});
      let modal,pending=false;
      button.addEventListener('click',event=>{
        event.stopPropagation();
        if(modal?.isConnected) { modal.focus();return; }
        const panel=doc.createElement('section');
        panel.className="tutorial-workbench-tokens-workshop";
        panel.setAttribute('role','dialog');panel.setAttribute('aria-modal','true');
        panel.setAttribute('aria-label',button.textContent);panel.tabIndex=-1;
        const title=doc.createElement('h2');title.textContent=button.textContent;panel.append(title);
        const choose=doc.createElement('select');choose.setAttribute('aria-label','Action');
        for(const recipe of recipes) {
          const option=doc.createElement('option');option.value=recipe.id;option.textContent=recipe.label;choose.append(option);
        }
        const form=doc.createElement('form'),fields=doc.createElement('div');
        const description=doc.createElement('p');
        const run=doc.createElement('button');run.type='submit';run.textContent='Run action';
        const close=doc.createElement('button');close.type='button';close.textContent='Close';
        const output=doc.createElement('pre');output.setAttribute('role','status');output.setAttribute('aria-live','polite');
        form.append(description,fields,run,close,output);panel.append(choose,form);
        function renderFields(){
          const recipe=recipes.find(item=>item.id===choose.value);fields.replaceChildren();
          description.textContent=recipe.description;
          for(const field of recipe.fields||[]) {
            const label=doc.createElement('label');label.textContent=field.label;
            const input=doc.createElement('input');input.name=field.name;input.type=field.type||'text';
            if(field.type==='number')input.step=String(field.step??'any');
            if(field.type==='checkbox')input.checked=!!field.value;
            else if(field.type!=='file')input.value=String(field.value??'');
            input.required=!!field.required;
            if(field.accept)input.accept=field.accept;
            label.append(input);fields.append(label);
          }
          output.textContent='';
        }
        choose.addEventListener('change',renderFields,{signal});renderFields();
        form.addEventListener('submit',async event=>{
          event.preventDefault();if(pending)return;
          const recipe=recipes.find(item=>item.id===choose.value),values={};
          for(const input of fields.querySelectorAll('input')) {
            values[input.name]=input.type==='file'?input.files[0]:input.type==='checkbox'?input.checked:input.type==='number'?Number(input.value):input.value;
          }
          pending=true;choose.disabled=true;run.disabled=true;close.disabled=true;
          for(const input of fields.querySelectorAll('input'))input.disabled=true;
          output.textContent='Running…';
          try {
            const value=await recipe.run({api,host,assets,storage,context,events,viewport,signal,onDispose},values);
            if(!signal.aborted)output.textContent=typeof value==='string'?value:JSON.stringify(value??null,null,2);
          } catch(error) {
            if(!signal.aborted)output.textContent=String(error.code||error.message||'unavailable');
          } finally {
            pending=false;
            if(!signal.aborted){choose.disabled=false;run.disabled=false;close.disabled=false;for(const input of fields.querySelectorAll('input'))input.disabled=false;}
          }
        },{signal});
        close.addEventListener('click',()=>void modal.close(),{signal});
        modal=api.ui.openModal(panel,{canClose:()=>!pending||signal.aborted});
      },{signal});
      onDispose(()=>{button.remove();if(modal)void modal.close();});
    });
  },
  stop() {}
};

    5. Permissions, failures and final test

    Every write is an explicit Run action. Reads use recipient projections; writes keep native permissions and fresh operation UUIDs. Scene update, object update, token move/configuration and combat use their real revision fields. Some native selection commands have no expected revision parameter in this release; the examples do not invent one. On conflict the recipe rereads current state and stops. Review it, then intentionally run a new operation. Multiple API calls are separate transactions: a completed earlier call is not rolled back if a later read fails. Deactivation aborts scoped work; it cannot undo a server commit.

    Use GM and controlling/noncontrolling player accounts. Test a locked token, blocked player movement, hidden token filtering, private condition filtering, a stale expectedVersion and a token from another scene. Condition advancement belongs to real combat events, not a local UI timer. Inspect after reconnect instead of replaying mutation events as side effects.
