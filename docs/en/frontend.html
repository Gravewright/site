    The application renders Jinja2 HTML on the server, uses Datastar for reactive signals and fragment updates, and runs JavaScript controllers for interactive workspaces. The game board uses PixiJS and a separate source/build pipeline. There is no single application-wide SPA build step.

    Follow a page from its template

    base.html loads the shared stylesheet, vendored Datastar, and gravewright_modules/frontend-api.js, which creates window.gravewright. The /inside workspace and game table extend that shell. table/page.html composes feature templates and loads table, map, journal, actor, dice and module controllers.

    Templates carry IDs and data-* attributes that native controllers and extension surfaces depend on. Changing one may affect the corresponding controller, Datastar signals, and module attachment. Check all three before renaming selectors or replacing an entire panel.

    modules/static/gravewright_modules/domain-api.js exposes the generated domain contract to pages and leased modules. file-api.js keeps file bytes in multipart requests and returns authenticated blobs; global-api.js owns account, campaign, administration and package adapters on the page lifetime. These adapters preserve caller cancellation and native permission checks. See the extended public API for MapBuilder, blueprints, ownership, library files and system-owned operations.

    Manual PDF fields

    For the complete player/GM workflow, see the PDF System guide. This section identifies the implementation and its validation boundaries.

    In a Gravewright PDF System character sheet, the GM can open a PDF and choose Map fields. Select text, number, checkbox or multiline text, then drag a rectangle over its area on the page. Add field creates a rectangle with the keyboard. Select a rectangle to rename it, change its percentage bounds, drag it or resize its lower-right corner. Arrow keys move the selected rectangle one display pixel (Shift: ten); Delete removes it and Escape cancels a gesture. Finish mapping returns to filling the sheet. Changes save automatically.

    Mappings belong to that actor or independent token copy, PDF source and page. They stay aligned through zoom and spread changes and coexist with native PDF form widgets. Authorized players can fill the fields; only the GM can change their definitions. The overlay leaves the original PDF file unchanged, including when downloading it. Deleting a rectangle retains its stored value. Number and single-line text fields can also be chosen for token bars.

    pdf_system/frontend/manual-fields.js owns stable identities and normalized display-page geometry; frontend/controller.js combines manual definitions with native widgets. static/gravewright_pdf_system/manual-editor.js owns gestures, selection and disposal. pdf_system/manual_fields.py validates at most 256 definitions across sources, page bounds, names, types and values, and enforces GM-only layout changes through the normal sheet-save service. Omitted layouts are preserved for older clients. The generated controller follows the existing map asset build pipeline.

    The GM can double-click a native or manually mapped field, or focus it and press F2, to open Field actions in the existing application modal. Choose a token value, enter a roll formula and label, or use one of six presets: d20, highest or lowest of two d20s, 2d6, exploding d6 and 4dF. @value references that field's current numeric value; an empty value is zero and checkboxes use zero or one. Formulas without @value also work on text fields. Clear the formula to remove the roll action. Assigning or removing a token-bar binding preserves the field's current value. Saving validates the complete candidate before updating the displayed sheet; Cancel and Escape discard the draft.

    Saved roll actions appear as buttons above the PDF for authorized editors. Players can also double-click a configured field; Alt+Enter rolls a focused field. The GM's double-click continues to open configuration, where Roll saved action executes the saved formula without applying the draft. Rolls use the native dice notation, publish to chat in the current scene context and retain normal request receipts and reconnect retries. Configuring an action consumes no randomness.

    pdf.fieldActions is optional and holds up to 256 source/field-bound roll definitions with a 512-character formula and a 48-character label. The server compiles formulas using the dice parser and compiler, preserving omitted actions and rejecting changes by non-GMs. frontend/field-actions.js builds isolated save candidates, preserves canonical bar values and expands the bounded numeric @value reference. static/gravewright_pdf_system/field-actions-editor.js owns the modal's draft and disposal.

    Reference field inserts @{field-key} into a roll or calculated formula. The picker shows readable names; manual keys remain stable when fields are renamed, and native PDF references retain their exact form-field name. Braces and backslashes in native names are escaped by the picker. Reference values are numeric and limited to the existing ±1,000,000 range. Calculated value formula accepts deterministic arithmetic, comparisons and the native numeric functions, with references to other fields. Clear it to return to ordinary editing. Calculated controls are read-only and update in dependency order. The server recomputes results on every sheet save, rejects circular references including aliases through token bars, and retains the previous canonical result when an input is temporarily nonnumeric or a calculation cannot execute.

    pdf.fieldBindings records validated original field addresses for references; bar overrides resolve against the current token mapping. Only the GM can change bindings or pdf.calculatedFields. The server's formulas.py and calculated_fields.py own validation and authoritative calculation; frontend/formulas.js mirrors the deterministic subset for immediate feedback. Archived field values and bindings remain available after removing a rectangle; diagnostics identify references whose visible field has disappeared.

    While mapping, Shift/Ctrl-click or drag a selection rectangle to select multiple fields on a page. The layout toolbar supports copying, pasting, duplication, six alignments, horizontal/vertical distribution and optional snapping to a five-point grid. Ctrl+C/V/D and Ctrl+Z/Shift+Z provide the same operations. The toolbar is inside Layout tools, initially collapsed in narrow sheet windows and expandable by keyboard or touch. Each gesture is one history step, limited to 50 steps in the active PDF. Undo restores definitions while retaining current character values; switching documents clears the history. Copies receive new UUIDs and remap formulas inside the selection. frontend/layout-editor.js owns geometry and layout-history.js owns definition snapshots and clipboard identities.

    Mapping library opens campaign templates for GMs. Save or replace the current mapping, apply a template to the current sheet or selected actors, and import or export versioned JSON. Templates contain rectangles, actions, calculations, bindings and optional document geometry, without PDFs, character values, names or media. Existing values are retained by field identity and canonical bars; templates do not merge unrelated fields by their visible labels. Independent token snapshots retain their own layouts unless explicitly applying a template to that open snapshot. Batch application validates all actor revisions before committing any changes. Stable manual IDs already used by another PDF in the same sheet cause a validation error rather than reassigning that PDF's fields.

    MappingTemplate and its initial migration belong to pdf_system. The /api/containers/<id>/pdf-mappings routes enforce GM and campaign boundaries, revision checks and operation receipts. Limits are 128 templates per campaign, 100 actors per batch and 1 MB per JSON import, in addition to sheet limits. Campaign archives include the templates and validate their portable bundles on restore. Template changes require a new application to update a character.

    Filled PDF downloads a separate flattened copy of every PDF page with the current field values, including repeated native widgets across pages. It renders through the bundled PDF.js at 144 dpi and writes JPEG page images in a minimal PDF container, preserving Unicode text as rendered by the browser. The original remains available separately. The copy contains no editable widgets or executable PDF content. Export rejects text that cannot fit its rectangle, excessive page/image complexity or a result over 100 MB, and downloads only after every page succeeds. It supports at most 100 pages, 16 million pixels per page and 128 million pixels per operation. Closing or switching documents cancels the work. The container follows the image-XObject and byte-offset structure of ISO 32000-1.

    The PDF mapping diagnostics button checks missing fields or references, calculation errors, absent pages and differences from saved document size, rotation or fingerprint. pdf.sourceMetadata keeps the expected document descriptor when applying a template; opening a PDF does not silently replace it. Diagnostics use authored labels as text and provide navigation to fields that are still present. Export and diagnosis never modify the original PDF.

    node --test gravewright/pdf_system/frontend/*.test.js covers the field model; manage.py test gravewright.pdf_system.test_manual_fields covers persistence and authorization. The isolated browser scenario tests/e2e/pdf_manual_fields.py exercises drawing, filling, navigation, native widgets, token copies, roles and Translator in English, Portuguese and Spanish. manage.py test gravewright.pdf_system.test_field_actions and tests/e2e/pdf_field_actions.py cover roll configuration, bar-value preservation, chat delivery, cancelled/invalid drafts, permissions and responsive translated modals. manage.py test gravewright.pdf_system also covers templates, calculations, metadata and campaign archive round trips. tests/e2e/pdf_workbench.py exercises the combined workflow and parses/renders the generated PDF with PDF.js.

    Map Builder workspace

    GET /game/<campaign_id>/map-builder renders maps/builder.html through maps/builder.py. It checks current GM membership and validates the optional folder query against that campaign. The new-scene chooser performs normal same-tab navigation; the builder uses the base shell with its own static/gravewright_maps/builder/ controllers, without mounting table runtime, scene subscriptions or the table workspace. Native effects use the dedicated preview described below.

    The table's scene directory reads the optional builderProjectId from the GM projection of maps.services.state(). It is resolved in one campaign-scoped ID query from the project's current scene link; non-GM projections do not include it. Linked scenes keep the same compact row and map icon, colored with --danger, and add Edit with MapBuilder beside the normal edit action in the context menu. Shift+F10 or the context-menu key opens the menu from a focused scene. Menus render in the directory's document, including detached windows; the edit action opens the editor in the main game tab. The project endpoint rechecks GM membership and campaign ownership on load.

    native-effects.js is a builder adapter to the same light, particle and shader catalogs as the tabletop. Its small eager builder-catalog.js bundle supplies presets without starting WebGL; builder-native.js loads lazily for visible sources. The editable entries are frontend/native/builder-catalog.js and frontend/native/builder-preview.js. The latter reuses PixiBoardRenderer and SceneLayers on a transparent overlay synchronized to the SVG camera and wall geometry. Hidden/empty layers, page hiding and disposal release rendering and animation resources. Native effects remain separate from the generated raster.

    frontend/native/builder-editors.js hosts the same LightEditor and EffectEditor widgets used by the game against a detached builder draft. Its builder-editor-model.js adapter maps the builder's light radius names and resolves compact preset references for GLSL editing without expanding an unchanged source. Transactional widget footers are enabled only in this host; the game's existing autosave behavior remains available to its normal host. Draft validation and preview never call scene commands. Saving returns one candidate to workspace.js, which checks editability and commits one project history step. Cancel/close disposes preview timers, shader validation and any nested prompt, preserving the project and live scene.

    static/gravewright_maps/wall-editor.js and the wall_editor.html template share the wall configuration window with the table's wall controller. Its builder host writes optional native presentation, channel, elevation and discovery settings to the source wall/door. Door and lever Smart Object behavior windows remain separate from physical wall configuration.

    builder/torch-model.js binds a decoration to native light/effect source rows. Mechanism state and flame illumination are independent; preview projects the mechanism's quarter turn and gates enabled components without rewriting source coordinates. model.js expands composed selections once for transforms and duplication, while object-removal.js reconciles ownership and Blueprint light references atomically. Component editor buttons reuse builder-editors.js and retain the selected parent. On the table, lever-controls.js hosts both lever and torch interactions, and image-components.js projects linked render nodes through image/selection previews without recreating GPU resources. The domain's torches.py validates scene-local ownership, applies authoritative transforms and flame gating, and keeps native group operations within map transactions.

    Entry is read-only. The Studio's workspace.js composes the editor controllers, navigation and drawing gestures. Its directly served sibling modules own these boundaries:

    Controllers receive explicit state and callbacks rather than importing the workspace or sharing globals. Persistence tests import its public factory; they do not extract function text from workspace.js. A disposed save owner cannot write a late acknowledgement over a recovered draft. model.js owns cell-space geometry and undo history, and viewport.js owns the independent SVG camera. Camera listeners, pointer capture, requests and resize observation end on pagehide; history restoration remounts the editor. builder_services.py owns campaign-scoped project revisions, retry receipts, validation, scene generation and updates. See Map Builder for the source schema, native geometry and raster boundaries.

    newDocument() creates one empty, generically named layer with a fresh UUID; the controller localizes its initial Layer 1 name. It creates no layers by object type. Schema-3 normalization preserves authored layers, including an empty layer list after removing the final empty layer. The server accepts that list only with no objects, and empty-map generation renders just the background. Version-1/2 upgrades retain their existing Base-layer conversion.

    All element kinds accept an authored name of up to 120 characters. Optional names stay omitted on unnamed legacy rows; regions and shaders retain their required names. The inspector supplies the existing Empty Object label for older unnamed controllers. element_names.py validates type, whitespace, length and NUL at the server boundary. Native edits, scene generation and linked updates preserve labels without replacing UUIDs or Blueprint targets. Static floor artwork remains baked; a dynamic surface carries its source name on the native image. The Selection inspector owns one name field per selected element, and layers, behavior catalogs and light/door choices prefer authored labels.

    The library's persistent tool strip exposes its additional controls through data-builder-dock-tool; existing panel tool selectors remain distinct. Tool changes flush the focused property before returning focus to the canvas. The strip scrolls independently on narrow screens and keeps a stable layout when the native light/effect library replaces the asset cards.

    The header mode selector honors optional editingMode: "tiles" | "paint"; omission defaults to Tiles without changing the source. Tiles and terrain Painting share layers, native objects, camera and project history. Existing floor.paint color/opacity still renders independently through SVG and the raster, multiplying shape coverage, texture alpha and opacity. Selecting the new terrain brush does not reinterpret those earlier styles or convert existing geometry. Floors retain their layer and transform contracts. SVG and Pillow use different antialiasing at coincident contour/cut boundaries; pixel comparisons keep interiors exact and isolate that subpixel boundary band.

    floor-painter.js owns transient floor gestures and commits one complete edit. model.js supplies swept brush footprints, family-aware flood fill, material sampling and atomic floor subtraction. floor-geometry.js supplies continuous contours and excluded cuts when snapping is disabled, along with shape-aware hit testing and source/raster budgets. The server validates the same optional floor shape contract and rasterizes its union-minus-cuts mask with bounded antialiasing. Preview fragments retain stable UUIDs; no-op strokes do not consume undo steps. layer-model.js counts layer contents and moves or merges them while preserving object identities and paint order. Layer duplication reuses atomic object duplication with an exact one-cell offset on both axes, new IDs and remapped internal Smart Object references. Bounds, global door overlap and project limits can reject the entire copy. Isolation is an editor filter; project visibility and native generation retain their existing semantics. Drawing controls belong to the auxiliary panel's Tools tab, leaving the canvas space available when the panel is closed.

    The Panels launcher opens the drawer's six linked tabs in a three-column grid. Each tab retains its own scroll position; the heading and tabs stay visible above the scrolling content. Arrow keys, Home and End navigate the tabs, while closing the drawer returns focus to its opener. Active brush settings precede the compact tool palette, and detailed brush help is a separate disclosure. Panel navigation and scrolling do not change the saved project or its history.

    Tiles repainting compares the topmost floor material before replacing coverage. An unchanged cell or completely matching free stroke retains its source rows without rerolling eligible family variants or adding history. Coverage accounts for the union of several floors and their cuts; another material above them blocks a match. Snapped gestures filter matching cells independently. Mixed free gestures replace their complete footprint, keeping geometry outside it. Coverage proofs have a bounded geometry work budget and reject atomically when it is exceeded. Terrain Painting uses its own radial brush representation rather than the earlier flat floor.paint opacity composition.

    Map Builder terrain painting

    terrain-painter.js owns a transient circular gesture, distance-spaced dabs and 50 ms stationary accumulation. It commits one floor.brush row per completed gesture and clears its timer on cancel, completion and disposal. The workspace owns pointer capture, shared brush size, mode controls, history and rendering; switching tools or modes cancels an active stroke. Tiles continues using floor-painter.js and its existing no-op and replacement semantics.

    terrain-brush.js and maps/terrain_brush.py evaluate the same radial kernel at absolute raster pixel centers. Hardness defines an inner plateau with linear falloff to the radius; dab alpha accumulates with bounded integer source-over rounding. The source stores local normalized points, horizontal/vertical radii, hardness and paint/erase operation in the floor box. Texture sampling retains the existing map-space phase and rotation, while the brush supplies coverage.

    An erase row applies destination-out only to earlier floors on its own layer. SVG nests the accumulated layer under its mask; Pillow keeps a separate RGBA surface for that layer. Later paint is outside the earlier eraser's scope. Merging an upper layer with erasers into a lower layer containing floors is refused, retaining that isolation. terrain-render.js caches disposable alpha-mask images by source signature and releases them on pruning/disposal; they are not campaign image assets. Limits bound dabs per stroke/document and the actual per-dab pixel work before raster allocation, and reject an oversized operation atomically.

    The Dungeondraft TerrainBrush reference and Terrain reference informed the separation between brush size/intensity and the terrain surface. Gravewright implements and persists its own radial brush contract.

    Shift and a left-button drag resize the floor brush using horizontal screen distance (40 pixels per cell). The anchored live guide follows Tiles snapping or the continuous terrain radius. Completion updates only editor preferences; Escape restores the previous size without a source/history write.

    builder/region-model.js authors named rectangles in cells and the explicit door pressure-plate preset. Regions share selection, layers, duplication and project undo, but are absent from the raster and player preview. regions.py derives private occupancy from validated token commands in their transaction; zones.py establishes a silent baseline for authored edits. The native features/regions modal displays GM state/count and edits zone settings.

    blueprint-editor.js edits a door, lever, torch or region's private draft through the shared mountModal helper; blueprint-model.js validates connections and simulates the selected event locally. The editor is native DOM/SVG without a graph library: nodes stay focusable elements on a translated and scaled plane, and native scrolling caused by focus is folded into that camera. Its own undo history covers only the open draft and ends with the modal. Saving applies one undo operation to the project. Generated doors keep the native door_state, while lever images keep lever.state; blueprint_runtime.py executes effects inside the existing map command transaction and receipt, which also records a GM-only run for automation-log.js, the table's Automation window. Lights and sounds use their current domains and realtime transport. Audience projections include only the active appearance, keeping graphs and inactive images private to the GM.

    blueprint-templates.js captures campaign-owned reusable snapshots, replacing only typed resource fields with bindings and exposing allowlisted scalar parameters. Applying a resolved copy is one draft undo operation; it creates no live dependency on the template. scene-network.js derives relationships from these same element-owned graphs, renders at most 40 cards per page and opens their existing editor. blueprint_network.py saves native rules with object/project revisions and a payload-bound receipt, atomically translating owned references back to the Builder source. The overview never executes rules.

    builder_dynamic.py promotes explicitly marked floors/walls to masked native image planes, leaving ordinary maps baked. Ordered paint/erase groups preserve floor alpha; surface-material.js samples replacement materials in the original texture frame and surface-group.js composes them on invalidation, outside the frame loop. Generated images belong to their scene and stay outside the asset library. Visibility and material actions mutate runtime state without creating files. Limits bound promoted surfaces, generated pixels, bytes and cache work. Preparation serializes dynamic/base raster work and releases each PNG buffer after storing an operation-owned artifact, before opening the write transaction. Repeated wall-material actions share a bounded request-local crop cache. Archive import validates the new surface metadata, aggregate buffer budgets and scene ownership of generated artwork/masks. Asset delivery enforces that ownership again for non-GM viewers; the renderer budgets all group buffers before allocation.

    blueprint_world.py validates presentation audiences and same-scene transport inside the existing command transaction. Recipient-filtered automation.presentation events are sent after commit and rechecked at delivery. automation-presentation.js displays authored text with textContent, opens the native journal window and deduplicates recent event IDs. Camera focus applies only to the viewed scene and requires a per-profile/device preference, off by default. Teleport uses the original authenticated trigger token, validates a free whole-token footprint inside the destination region and queues arrival presence after the current object cache is persisted. A durable arrival gate prevents return loops until the token leaves the region; scene navigation and party membership are unchanged.

    The Interactive object catalog in Builder selection, Ready-made models in the object context menu and the node editor's Object catalog share 14 editable generic lever Blueprints. Models cover switches, chests, secret passages, books, altars, warning traps, bells, pressure plates, dice requests, quest activation/completion, entrance signs, timed switches and door buttons. The configuration modal offers optional sound/volume and active-state artwork; unchecked options produce no sound node or image override. State artwork comes only from Object assets and restores the original artwork while inactive. Applying a model keeps object identity and geometry; replacing authored behavior requires confirmation in the application modal and can be undone. The trap warns on entry while armed; it does not apply system-specific damage. The inspector's Behavior choices open the same configuration modal. Property section modals reuse the inspector controls and save through its existing commits and history.

    Blueprint V2 requestRoll stores a validated dice expression (up to 512 characters), label (up to 48), visibility (public or gm) and audience. Audience controls offer the triggering user, all players, one player or chosen users. One player persists as the compatible users scope with one UUID. Authorized recipients receive a native modal and explicitly choose Roll; the normal server dice service validates and posts the result to chat. The event UUID identifies the same logical roll per user across retries and tabs, and the originating scene stays fixed. Streamers cannot receive roll requests. The action continues immediately: it does not branch on a roll result.

    Open journal uses the existing showHandout contract for diaries, quests and quest boards, without granting reading access. setQuestStatus stores a quest journalId and one of draft, available, active, completed, failed or archived. The server validates campaign/type and applies the fixed GM-authored action through the journal service within the map transaction; players do not gain journal edit permission. Rehearsals report quest changes and roll prompts without persisting journals or delivering player windows. Templates, delayed references and archives preserve these bindings and authored roll labels.

    Blueprint V2 all/any are pure Boolean values with inputs a–d and result. Connected inputs evaluate in fixed order without short circuit; fewer than two returns False. Shared nodes are memoized only within the current event. Both Python and JavaScript enforce Boolean wires, one source per input and graph cycle/size limits. The palette groups the nodes under Logic, and the card shows connected-input count; simulation and the GM log display evaluated results.

    Blueprint V2 elementGroup is a pure typed ordered set: name (1–80 characters), memberType (element, light, sound) and 1–32 unique UUID targetIds. Its targets output becomes elementset, lightset or soundset. lightReference.targetId outputs light: light; soundReference.trackId outputs sound: sound. Legacy reference retains its door: element output ID and also addresses ordinary live images, whose state is null. Baked walls/floors remain outside this contract. acceptsDataType(port, type) handles acceptedTypes on Target ports: element actions accept an element/set, light and sound actions their corresponding resource/set, transforms an element/light or either set. Get property remains single-element. A connected Target overrides the legacy resource binding or Self; stale UUIDs stay connected and are skipped/logged, never silently redirected. Group order is explicit and each expanded action counts against the existing action budget.

    move stores finite dx/dy offsets in cells, each bounded by ±1,000; rotate stores finite relative degrees bounded by ±36,000. blueprint_actions.py uses native image, door, light and region validators inside the command transaction. Rotation uses each target's own center, and presence rectangles require multiples of 90 degrees. Linked torch components follow the image. Authorized transforms acknowledge owned geometry without changing the source; scene update reapplies authored transforms, preserving conflict protection for unrelated manual edits. setInteraction.enabled and setRegion.enabled are strict Booleans. The former gates direct player requests and pointer/keyboard/torch-flame controls while GMs retain manual override; it does not gate authored automation. The public native projection carries interactionEnabled; omitted authored flags retain the enabled default. Runtime interaction flags survive update while their authored defaults are unchanged; an explicit authored change wins. Runtime region enabled state is preserved while source enabled/layer settings stay unchanged; authored changes win and quietly baseline occupancy. Native copies and campaign archives retain configuration; UUID remapping touches typed references/group members, not authored scalar strings. Deleting a legacy resource action bridges only execution edges; data wires never become execution wires, and stale new refs/groups remain inert.

    Archive import uses remap_omitted_bindings for new sound references/sound-group members and presence-filter actor/token IDs when their records are omitted. A model/UUID lookup allocates one fresh inert UUID per missing identity and reuses it in project documents, native data and generation manifests. Imported links remain inert until replacement resources are chosen; names, event/group labels and authored scalar text are preserved, including text that happens to resemble a UUID.

    eventContext.property selects a readonly typed value.     Blueprint V2 also implements getVariable, setVariable, compareValue and emitEvent. Failures roll back memory and other effects together.

    simulateGraph accepts an optional sixth argument {variables: {element: {...}, scene: {...}}}.     Blueprint V2 switch and random are execution controls with dynamic ports, without per-node automationMemory. Switch stores valueType, typed fallback value and one to four exact {id, value} cases. Case IDs are unique members of case1–case4, and case values are unique within the selected Boolean/number/text type; Boolean permits at most two. Scalar limits match variables. Value input type derives from valueType. Strict equality selects one configured case ID or default, using the fallback only when Value is disconnected. Connected reads use the event snapshot.     Random stores two to four weights: integers from 0 to 1,000 with positive sum. Its ports are branch1 through the configured count. The draw covers the total weight of all configured outputs, including disconnected ones. A zero weight cannot win; a disconnected selected branch ends the path without another draw. executionOutputs(node) returns dynamic descriptors and nodeOutputs(node) derives their IDs.     Board layers and resource lifetimes

    The maps/frontend/ tree separates entity models, feature models/UI, shared utilities, and the game-board widget. The board widget coordinates rendering, input, tile scheduling/cache/prefetch, native layers, vision polygons, lighting and shaders. Feature code contains walls, tokens, drawings, measurements, effects, and selection. Algorithm tests live beside the relevant models and are bundled by maps/scripts/test_models.cjs for Node's test runner.

    Use one consistent coordinate system across controllers and renderer calls: logical scene pixels, top-left origin, token centers as anchors. Camera pan/zoom converts scene positions into CSS viewport coordinates; device pixel ratio affects rendering resolution. Mixing these units causes selection, token and lighting misalignment. The extension overlay API exposes explicit conversion helpers instead of exposing the PixiJS renderer.

    Async work belongs to a page, board, module activation, or individual mount. Lifetime cancels API calls and disposes subscriptions; map source code has its own shared lifecycle helpers. Add/remove listeners and observers with their owner. Release rendering resources and pending work during board teardown or scene changes. A listener or cached API handle that outlives its owner can update the next scene with old data.

    Updates to the current scene preserve camera pan/zoom, token art and mounted layers, including revisions caused by teleport automation. Only a scene change resets the camera. Raster revisions refresh existing tile keys by URL and keep the previous decoded tiles visible until replacements are ready; superseded requests cannot paint an older revision. A failed replacement retains its current art while the bounded retry runs. Region occupancy and geometry refresh their own overlay, keeping unrelated floor, light and shader resources mounted.

    Token acknowledgements and realtime snapshots can carry native teleports: [{id, version}] metadata, filtered against the recipient's visible tokens and their exact revisions. The token workspace remembers each accepted teleport revision across normal reads. It bypasses movement interpolation and recreates only that token's Pixi object at its destination; repeated delivery keeps the same replacement. Logical identity, selection and sheet data remain unchanged, and older asynchronous art loads cannot restore an earlier object.

    Successful token commands apply the authorized token snapshot in their acknowledgement. They do not issue another token GET or request scene layers; committed scene changes arrive through the existing realtime subscription. Failures and version conflicts still reload authoritative state. A movement with no displacement and no traversed path does not save or enter the busy state. Paths that leave and return to the same position remain real operations so region entry/exit automation is preserved.

    The token workspace saves silently, including when a confirmation takes longer. Pending commands keep the interaction guard for concurrent edits. Errors and route instructions remain immediate; there is no saving notice or notice timer. Unchanged status text is not rewritten on every paint.

    Local token previews reuse the static scene key and image reconciliation while their immutable scene inputs remain the same. They do not walk all native image transforms or reconstruct the component-origin index on every frame. A new image snapshot still reconciles its transforms and artwork; changed walls, effects, scene identity and role still invalidate their owning resources.

    Movement notifications refresh scene layers and tokens without rebuilding the unchanged actor directory or combat panel. Actor/combat edits and other token commands retain the relevant notifications. Paired layer/token notifications deliver spatial audio once through the token refresh; independent layer edits still refresh audio. Live authorization and extension change hooks remain in place.

    Same-scene teleport advances token revisions, not scene metadata or raster revisions. Its layer/token notifications carry region and appearance changes without requesting a new scene manifest or changing existing tile URLs. Repeated portals therefore retain the decoded floors and raster textures already loaded.

    Native image updates

    SceneImageArt reconciles ordinary image textures independently of the static scene key. A source change keeps the sprite and its previous art until the new texture is decoded; late results cannot overwrite newer state or a closed scene. Current art survives same-scene light/geometry rebuilds. Composed surfaces and grouped floors use a separate cache with the same lifecycle. Unchanged composites rebind synchronously during effect rebuilds; material replacement retains current art until decoding completes. Changed masks, geometry, group membership or visibility revoke obsolete coverage immediately. Composition closes all input bitmaps, including failed and cancelled loads, and publishes no partial floor. Each art cache retains at most eight idle textures and 16 MiB of idle decoded RGBA data, evicting the least recently used entries. Scene/role changes and disposal abort pending loads and release textures/bitmaps. Only art in the authorized projection is requested; inactive appearances are not prefetched.

    Token-art references wait for a pending unload of the same URL before loading again. Pixi's loader can otherwise return its old cached texture while unloading is about to destroy it. Independent URLs remain concurrent. Dispose applications with explicit removeView: true, releaseGlobalResources: false options: boolean true also releases process-wide pools still used by other boards and previews. Scene-owned textures and renderer resources still end with their owner.

    GM-private images and Empty Object markers remain visible at 55% opacity in all workspaces, with selection and interaction restricted to GM. Private drawings multiply their authored opacity by the same factor. Server projections still exclude private elements from player/streamer clients.

    Realtime delivery sends committed maps.layers and tokens.state before their dependent audio/combat refreshes. Every delivery retains its own authorization check. Token-triggered changes may share the same scene revision; never discard snapshots solely because that revision is equal.

    Lighting and vision work

    SceneLayers calculates light occlusion once for each static scene key and reuses those polygons for masks, the light atlas and the GM darkness veil. createVisibilityContext shares wall indices and keeps at most eight filtered subsets for finite ranges or elevation. Preserve the original ray arithmetic and wall membership: changing a BVH can change rounding at coincident endpoints.

    Torch and pulse frames update additive Pixi sprites over immutable falloff textures. Shaders receive a GPU render texture; only particles that respond to light request CPU samples, capped at eight samples per second. Profiles keep their existing animation rates. A scene owns the texture pool and releases it after shader bindings, the atlas and sprite layers.

    Vision changes coalesce once per animation frame. Scenes with at least 128 wall segments use the same-origin module worker emitted as vendor/visibility-worker.js; smaller scenes and unavailable workers use the same geometry synchronously. The worker keeps one active job and the latest pending snapshot, transferring coordinate buffers. Native observers carry a sourceId so movement can retain the last completed view while the next calculation runs. Selection, range, elevation, cone and preview changes revoke that view immediately; wall and scene changes terminate the old worker. Never reuse visibility across those boundaries or quantize the configured vision range or token positions. Pending movement retains the existing veil texture until a result arrives; unrestricted GM vision reuses its static veil without repainting on token moves.

    Compare full frames and completed worker jobs when profiling. Queuing work is not completion, and headless software WebGL results do not establish hardware GPU performance. Rebuild both board and worker entries together with the normal asset build.

    Extending the interface

    The host's SurfaceRegistry accepts gravewright.ui.register(domain, declaration) and returns an unregister function. It supports registered table surfaces plus app.shell and inside.content. A mount receives {root, context, api, signal, onDispose}. It gets a fresh lifetime and a dedicated root; failed mounts are cleaned up, and replaced native elements have their previous visibility restored. This global registry permits one replacement per domain.

    Installed signed packages use ModuleRuntime instead. Its registrations are synchronous during module activation, its calls carry module identity/lease/revision, and competing replacements are chosen using table preferences. Use the module's register callback for installed packages; global UI registration is for host-page integrations and has different ownership/selection rules. Full examples and supported names are in modules.

    Run the checks affected by the source you changed:

    sh
    node --test tests/modules/*.test.mjs tests/effects/*.test.mjs
npm test --prefix gravewright/maps/frontend
uv run --locked python tests/e2e/frontend_api.py

    For rendering or interaction changes, use relevant scenarios under tests/e2e/, including mixed_selection.py, token_routes.py, light_rendering.py, effect_geometry.py, effect_pixels.py, map_prefetch.py and realtime.py. The browser harness and dependencies are explained in testing. Test player and GM sessions where behavior is permission-dependent, and check disposal/reconnect when adding subscriptions. Keep labels and message catalogs aligned with the application's supported languages.
