    All extension capabilities and where to implement them

    An explicit method-by-method map to projects, local helpers, surfaces, server integrations and release limits.

    How to use this map

    This index crosses public contracts from host 0.3.1, revision 0e91fef, with implementation projects. It covers 139 domain API methods, 17 original SDK operations, 13 surfaces and lifecycle helpers. Each method links to runnable code, inputs and a test, rather than promising arbitrary unsupported combinations.

    Begin with the outcome you want to build. Use this table to locate a specific capability. A recipe can combine create/configure/read/remove because they are parts of one feature. Actions execute on click and destructive operations are identified. Use a disposable installation/campaign.

    Choose the package structure

    DeliverableStructureComplete tutorial
    Journal, sheet, cards, audio or table toolBrowser package with entry and registerFirst module and families below
    RPG sheets, types, initiative and catalogOne system package with entry/assets/content.compendiumsComplete system
    Translate your own modulePrivate api.i18n catalogsTranslation and events
    Add an installation languagelocales package without system/DjangoLanguage package
    Trusted Python routes/servicesDjango package, owner/Runner activationServer integration
    Distribute an approved releaseImmutable ZIP, hash, signature and HTTPS catalogPublication

    There is no global module-type enum. A compendium can mean a mutable campaign pack, an installed system catalog or an operator-managed local catalog, with different rules. Mounting depends on its surface rather than your module’s label.

    Every domain method

    Generic methods take api.domain.method(payload,{signal,requestId}) with recipe-specific fields. Reads do not need requestId. list/get project authorized state. actors.sheet, dice.roll, table.search, chat.remove and other convenience methods use their own demonstrated signatures. JavaScript method names differ from native Python action names.

    Map Builder and visual automation

    All four door/lever/torch/region owners, execution/data connections and 44 node.type values have complete graphs, JSON and editor steps. The node catalog explains targets, resources and effects. Use native Test behavior/playtest before live application. These graphs are development documents, not a browser API for importing arbitrary JSON or a new manifest field.

    The scene tutorial implements public layer/object operations. Adding new kinds or editor ports requires a core contribution and tests; 0.3.1 does not promise a plugin API for arbitrary node-type registration.

    Server integrations and release boundaries

    The Django integration implements Context.from_request, public commands, authenticated/CSRF routes and after-commit hooks. Python facades api.actors/tokens/maps/journals/items/combat/cards/audio/compendiums/resources/chat/dice/table/events have signatures in the reference. Context retains IDs rather than cached authority, and each service checks access. Account/admin/package/campaign management are global application adapters rather than methods on a mount’s api; see adapter reference for operator tools.

    There is no maps.create or audio.upload domain SDK method: tutorials prepare scenes/files through native UI and then use supported public operations. Browser modules do not receive arbitrary SQL/Python execution, implicit GM powers, campaign switching through foreign UUIDs or hidden-data bypasses. system.combat supports declarative initiative. Existing Python providers are trusted server code, not permission to distribute a new RPG as a system plus separate Server Rules companion. Explain unsupported requirements while preserving the requested host version.

    Maintain coverage when the host changes

    This map uses a versioned frontend.json/registry.json snapshot in extension-contracts.json. For a host upgrade, compare actual source files/revisions, update projects and run their recipes against real services. Matching names alone does not prove payload, permission, visual or transaction behavior. Repeat mutation/snapshot tests in new fixtures.
