    How to create a scene tools module

    Build a working module to inspect scene layers, edit metadata, manage folders, draw a native door and broadcast a test scene.

    The project you will build

    Create Scene workshop, a browser module with a native workbench modal. Follow a concrete sequence: inspect an existing disposable scene, rename it, organize its folder, create/edit/operate a door and deliberately broadcast it. Delete the test data only after the token and combat tutorials.

    Target host: Gravewright 0.3.0. Actions run only when you click Run action, using the signed-in account. The demonstration panel is English. Each recipe specifies inputs and an observable result.

    1. Create the files

    Create a folder named maps-workshop. Save the complete files below as UTF-8, or download the project. manifest.json belongs at the root. No npm dependencies or JavaScript build is required.

    text
    maps-workshop/
  manifest.json
  main.mjs
  recipes.mjs
  styles.css
  LICENSE.txt

    In a disposable campaign, create an empty scene at least8×8 cells using the native Scenes → New scene → Map Builder flow, then Generate scene. Start with no valuable scene content. The public browser domain API has no maps.create method for a new raster/Builder project. Use Map Builder for authored projects; native source generation remains separate from the commands below.

    2. Package, install and activate

    From the project folder, run in PowerShell:

    powershell
    python -m json.tool manifest.json
python -m zipfile -c ../maps-workshop-1.0.0.zip manifest.json main.mjs recipes.mjs styles.css LICENSE.txt
python -m zipfile -l ../maps-workshop-1.0.0.zip

    On Linux/macOS, replace python with python3 in the same commands. The archive listing must show manifest.json at its root. As installation owner, open Inside → Modules → Install module → Install from ZIP, select the ZIP and click Install. As GM, open the campaign, select its Gravewright button → Extensions and Activate version 1.0.0 of Scene workshop. Close that menu and click Scene workshop. See your first module for screen-by-screen instructions.

    The package stays inactive until selected for the table. Test one demonstration extension at a time because their launchers share a position. For changed bytes, increment version to 1.0.1, build another ZIP, install and activate that version; do not edit installed files.

    3. Run each recipe

    Inspect scenes, folders and native layers

    Run with the Scene ID blank first. Copy the test scene ID, enter it and run again to inspect walls, images, lights, fog, lighting and their returned versions.

    javascript
    async ({api,context,signal},v) => {

  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    const directory=await api.maps.state({},read);
    const layers=v.mapId.trim()?await api.maps.layers({mapId:v.mapId.trim()},read):null;
    return {directory,layers};
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.maps.state({},read);
    throw problem;
  }
}

    Expected result: Authorized scene/folder IDs, activeMapId and navigatingMapId; selected native layer state when supplied.

    How to verify: Compare the GM scene directory with a player account. Player state must omit private scenes, regions and private graph data.

    Rename the test scene and set grid visibility

    Use a disposable scene. Name and gridVisible are supplied settings; other scene settings remain unchanged. Do not send the entire projected scene as settings.

    javascript

    Expected result: The same scene ID with the chosen name, grid visibility and a new integer version.

    How to verify: Open native scene settings and verify name/grid while checking that imageScale, gridSize and measurement units remain as before.

    Draw a native test door through updateObjects

    Use a scene at least 8 cells wide. Coordinates are scene pixels, not the cell coordinates used by token.move. The endpoints must differ. This creates a plain native door with no blueprint or image dependency.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    await api.maps.get(v.mapId,{},read);
    const result=await api.maps.updateObjects({mapId:v.mapId,area:'walls',action:'create',data:{x1:v.x1,y1:v.y1,x2:v.x2,y2:v.y2,kind:'door',door_state:'closed'}},write());
    return {created:result.wall,layers:await api.maps.layers({mapId:v.mapId},read)};
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.maps.state({},read);
    throw problem;
  }
}

    Expected result: A wall entry with kind door, an ID and version. Copy its ID.

    How to verify: Open Walls in the native scene and find the horizontal door. Inspect its projected endpoints.

    Adjust a door endpoint with its object version

    Use the door created above. Only x2 changes; the native validator retains its other fields. Scene version and object version are different.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');

  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});

    if(problem.code==='conflict'&&!signal?.aborted) await api.maps.state({},read);
    throw problem;
  }
}

    Expected result: A longer/shorter door, same ID, incremented object version.

    How to verify: Verify that x1/y1/y2, presentation and barrier channels are preserved. An interleaved native object edit must cause conflict.

    Open or close the plain test door

    Enter open, run, then enter closed and run again. This recipe deliberately uses a plain door. On a Smart Object the same interaction may execute authored graphs instead of applying a simple toggle.

    javascript
    async ({api,context,signal},v) => {
  if(context.role!=='gm') throw new Error('GM required');
  const read={signal};
  const write=()=>{
    if(signal?.aborted) throw Object.assign(new Error('Mount closed'),{code:'cancelled'});
    return {signal,requestId:crypto.randomUUID()};
  };
  try {
    if(!['open','closed','locked'].includes(v.state)) throw new Error('Use open, closed or locked');
    const layers=await api.maps.layers({mapId:v.mapId},read);
    const door=layers.walls.find(row=>row.id===v.doorId&&row.kind==='door');
    if(!door||door.blueprint) throw new Error('Choose the plain tutorial door without a blueprint');
    return await api.maps.updateObjects({mapId:v.mapId,area:'walls',action:'door',data:{wall_id:door.id,door_state:v.state}},write());
  } catch(problem) {
    if(problem.code==='conflict'&&!signal?.aborted) await api.maps.state({},read);
    throw problem;
  }
}

    Expected result: The plain door opens/closes in the native scene.

    How to verify: Observe geometry and blocking. Test player interaction separately in the real native controls, including locked-door refusal.

    Broadcast the prepared test scene

    Choose the disposable prepared scene and explicitly check the broadcast box. activate makes the scene player-visible and changes the campaign broadcast.

    Expected result: activeMapId equals the scene ID; connected players switch to it.

    How to verify: Use a second player account. Verify the broadcast changes only after Run action with the checkbox selected.

    Delete only the tutorial door

    Use only the door created in this tutorial and confirm. A Smart Object deletion can have authored destruction effects; the tutorial plain door has none.

    How to verify: Inspect walls before/after and confirm only the copied door ID was removed.

    4. Understand and adapt the complete files

    main.mjs renders the launcher and form. recipes.mjs owns behavior: change the chosen recipe’s run function while keeping its signature. The form passes real number, boolean and File values, blocks overlapping requests and renders using textContent. It does not evaluate user-provided code. api, host, assets and storage belong to the mount; signal cancels work on deactivation. The modal stays open during pending work and is released when the mount aborts. Each business function remains responsible for revisions, permissions and transaction sequencing.

        event.stopPropagation();
        if(modal?.isConnected) { modal.focus();return; }

        panel.setAttribute('role','dialog');panel.setAttribute('aria-modal','true');

        }
        const form=doc.createElement('form'),fields=doc.createElement('div');
        const description=doc.createElement('p');
        const run=doc.createElement('button');run.type='submit';run.textContent='Run action';

            if(field.type==='number')input.step=String(field.step??'any');

            if(field.accept)input.accept=field.accept;

          output.textContent='';
        }

        form.addEventListener('submit',async event=>{
          event.preventDefault();if(pending)return;
          const recipe=recipes.find(item=>item.id===choose.value),values={};
          for(const input of fields.querySelectorAll('input')) {
            values[input.name]=input.type==='file'?input.files[0]:input.type==='checkbox'?input.checked:input.type==='number'?Number(input.value):input.value;
          }
          pending=true;choose.disabled=true;run.disabled=true;close.disabled=true;
          for(const input of fields.querySelectorAll('input'))input.disabled=true;
          output.textContent='Running…';
          try {
            const value=await recipe.run({api,host,assets,storage,context,events,viewport,signal,onDispose},values);
            if(!signal.aborted)output.textContent=typeof value==='string'?value:JSON.stringify(value??null,null,2);
          } catch(error) {
            if(!signal.aborted)output.textContent=String(error.code||error.message||'unavailable');
          } finally {
            pending=false;
            if(!signal.aborted){choose.disabled=false;run.disabled=false;close.disabled=false;for(const input of fields.querySelectorAll('input'))input.disabled=false;}
          }
        },{signal});
        close.addEventListener('click',()=>void modal.close(),{signal});
        modal=api.ui.openModal(panel,{canClose:()=>!pending||signal.aborted});
      },{signal});
      onDispose(()=>{button.remove();if(modal)void modal.close();});
    });
  },
  stop() {}
};

    5. Permissions, failures and final test

    Every write is an explicit Run action. Reads use recipient projections; writes keep native permissions and fresh operation UUIDs. Scene update, object update, token move/configuration and combat use their real revision fields. Some native selection commands have no expected revision parameter in this release; the examples do not invent one. On conflict the recipe rereads current state and stops. Review it, then intentionally run a new operation. Multiple API calls are separate transactions: a completed earlier call is not rolled back if a later read fails. Deactivation aborts scoped work; it cannot undo a server commit.

    Test GM/player scene filtering, one stale scene revision, one stale door revision, denied folder cycles and deactivation during a read. Activation explicitly broadcasts to players. Map Builder boundary: this package does not author Blueprint JSON or call private Builder routes. Use the real Smart Object editor, Simulate and Test behavior to create automation, then Generate/Update scene. Four Blueprint kinds, 42 complete node examples and execution/data connections provide complete graph recipes.
